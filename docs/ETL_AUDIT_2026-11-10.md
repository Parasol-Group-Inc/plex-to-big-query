# ETL audit, 2026-11-10 (after the ODBC recovery)

Read-only audit of the Plex → BigQuery ETL, two days after Plex's prod ODBC recovered
(2026-11-08 ~04:45 MT). Window: 2026-11-08 12:00 UTC to 2026-11-10 ~16:30 UTC.

**Three independent checks:**
- **Runs and logs:** a Sonnet agent (medium effort) checked the dispatch log, job_run_log, Cloud
  Run and Cloud Logging.
- **Data:** an Opus agent (low effort) checked freshness, every view, totals rebuilt from the raw
  tables, and duplicates.
- **Live screens:** Claude read Plex's live screens (dry run, nothing written) and compared them
  with ODBC and the reports.

**Verdict: the ETL is healthy.** The reports' numbers match Plex, with one exception: revenue is
valued as quantity × price, so it is $1,898.08 higher than Plex's invoiced figure for November.
Fixes are proposed, not made.

**Why the revenue report differs:** it values each shipped line at quantity × price. Plex's screen
and the invoices show what was invoiced:

| Invoice | Part | Plex (invoiced) | Report | Report − Plex | Why |
|---|---|---|---|---|---|
| INV0000068 (10-27) | 93105-00KAYAN-0 | 189.75 | 379.50 | +189.75 | 75 of 150 units invoiced |
| INV0000180 (11-06) | 14535 (Go-Live Temp) | 196.20 | 1,962.00 | +1,765.80 | −1,765.80 adjustment on account 41000 |
| INV0000190 (11-09) | 93129-00GENE9-0 | 548.25 | 645.00 | +96.75 | invoiced at 85% (15% off) |
| INV0000207 (11-09) | 93011-00KAYAN-1 | 319.95 | 355.50 | +35.55 | invoiced at 90% (10% off) |

**Credit memo:** CM0000001 (−$11,760, 11-05) reverses INV0000161 on SH00206, which Plex removed.
The two cancel out in Plex. The report counts neither, so it is also net zero. The data agent read
this as "revenue $11,760 too high"; the screen comparison shows it is not.

**Production on 11-06:** last night the screen had 7 more records than ODBC. Today both have 1,101,
so those records were removed in Plex.

## Proposed fixes

Not made; for Emilio to decide.

1. **Revenue: value invoiced lines at the invoiced amount.** For a shipped line that has an
   invoice, use the invoice's revenue-account amount (`Accounting_v_AR_Invoice_Dist`, Credit −
   Debit on `4%` accounts, by `Shipper_Line_Key`). Otherwise keep quantity × price. That makes
   `shipping_revenue_report`, the revenue summary and the scorecard Revenue tile equal Plex's
   Shipping Revenue screen (November: −$1,898.08). It needs a business decision: the tile today
   shows shipped value at list price, not invoiced value.
2. **Test MSL view (D29):** create `PlexTest.msl_rules` and `msl_item_inputs` with prod's schema,
   or drop `approaching_msl_report` from `reports/test/sales_orders.yaml`. This stops the nightly
   "PARTIAL TEST" email.
3. **Two empty views to explain:** `inventory_avg_daily_usage_report` and
   `mfg_job_schedule_gate_stats_report` return 0 rows.
4. **`inventory_activity_report`** has been empty since 08-12 (its Plex sources return nothing):
   find another source or retire it.
5. **Minor:**
   - move the 4:47 AM test retry after the nightly cascade;
   - fix the two missing board columns behind the Label Design push warning;
   - a freshness monitor should skip 0-row tables.
